# Product Requirements Document: Goal-Oriented vs Freestyle Scripture Memorization Flows

## Project Overview
Transform the existing scripture memorization web application to support two distinct user flows: a primary goal-oriented approach and a secondary freestyle approach. This will enhance user engagement and provide structured progression paths for scripture memorization.

## Current State
The application currently has:
- Individual components (blanks, memorize, input) that work independently
- A basic goal system with progression tracking
- Blanks component with adaptive difficulty using MemorizationPracticeService
- Home page that shows recent attempts and goals

## Goals and Objectives

### Primary Goal
Implement a dual-flow system where users can choose between:
1. **Goal-Oriented Flow** (Primary): Structured memorization with progression tracking
2. **Freestyle Flow** (Secondary): Independent component usage without goal constraints

### Success Criteria
- Users are strongly directed toward goal creation on the home page
- All components (blanks, memorize, input) can operate in both goal-oriented and freestyle modes
- Goal-specific blanks progression is maintained separately from freestyle progression
- Seamless promotion from blanks to recitation within goals
- Clear navigation between goal context and freestyle usage

## Detailed Requirements

### 1. Home Page Redesign
**Priority: High**
- Redesign home page to prominently feature goal creation as the primary call-to-action
- Maintain access to freestyle mode but make it less prominent
- Show existing goals with clear progression indicators
- Provide quick access to continue working on existing goals

### 2. Goal-Oriented Component Integration
**Priority: High**
- Modify blanks, memorize, and input components to accept goal context via URL parameter (?goalId=xyz)
- When in goal context:
  - Show goal-specific progress and context in component UI
  - Automatically associate results/attempts with the goal
  - Provide navigation back to goal overview
  - Use goal-specific progression data instead of global data

### 3. Goal-Specific Blanks Progression
**Priority: High**
- Extend MemorizationPracticeService to support goal-specific storage
- Each goal maintains independent blanks progression for the same passage
- Modify storage structure to include goal context
- Ensure complete isolation between different goals' progression data

### 4. Blanks-to-Recitation Promotion System
**Priority: Medium**
- Integrate with existing goal promotion system
- Add logic to detect when user reaches maximum blanks difficulty
- Provide manual promotion trigger in goal interface
- Show promotion suggestions when criteria are met
- Update goal status appropriately when promoted

### 5. Component Dual-Mode Support
**Priority: High**
- All components must work seamlessly in both goal and freestyle modes
- Freestyle mode maintains current behavior and storage patterns
- Goal mode uses goal-specific storage and shows goal context
- Clear visual indicators of which mode the user is in

### 6. Navigation and User Experience
**Priority: Medium**
- Implement breadcrumb navigation showing goal context
- Add "Return to Goal" buttons in goal-oriented component views
- Ensure smooth transitions between goal overview and component usage
- Maintain deep-linking capabilities for both modes

### 7. Data Architecture Updates
**Priority: High**
- Modify storage services to support goal-specific data isolation
- Update MemorizationPracticeService for goal-aware storage
- Ensure backward compatibility with existing freestyle data
- Implement data migration if needed for existing users

## Technical Implementation Areas

### Frontend Components
- Home page redesign with goal-centric UI
- Component modifications for dual-mode operation
- Goal-specific UI elements and navigation
- Promotion system integration

### Services and Data Layer
- MemorizationPracticeService extension for goal support
- StorageService updates for goal-specific data
- Goal progression logic integration
- Data migration utilities

### Routing and Navigation
- URL parameter handling for goal context
- Route guards and navigation logic
- Deep-linking support for both modes

### User Interface Design
- Goal creation and management interfaces
- Component mode indicators
- Progression visualization
- Promotion system UI

## Success Metrics
- Increased user engagement with goal creation
- Higher completion rates for scripture memorization
- Improved user retention through structured progression
- Seamless user experience across both flows

## Technical Constraints
- Must maintain backward compatibility with existing data
- Should not break current freestyle functionality
- Must work within existing Angular architecture
- Should leverage existing services and components where possible

## Future Considerations
- Analytics integration for goal vs freestyle usage patterns
- Advanced goal types and progression paths
- Social features for goal sharing
- Mobile app considerations for dual-flow support
